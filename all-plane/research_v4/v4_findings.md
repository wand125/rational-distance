# 全平面探索 v4：追加除外・生成器の改善・否定結果

## 対象と限界

`all_plane_gap_v4.cpp` は、凍結した v3 と共通の厳密再構成コードを利用する。
全平面の対称領域で

\[
n=N/2,\quad u=(B-A)/2,\quad v=(C-A)/2,\quad h=u-v,
\qquad 0\le v\le u\le n
\]

を列挙する。ここで探索上限は最小座標分母 **N** であり、距離・座標の絶対値の
上限ではない。既存の算術上限 `N<=2000000` は変更していない。

今回 v4 の探索全体を検証・計測した上限は **100,000 と 200,000**。
2,000,000 の全探索は起動していない。以下の「候補」は、必要条件を通って
厳密再構成へ渡した整数パラメータであり、4距離解を発見したという意味ではない。
今回の計算で4距離解は0個だった。数学的な新規性は主張しない。

## 完全なパラメータ集合の比較

単なる個数比較ではなく、凍結 v3 が出力する **全 `(N,p,q)` 集合**へ新しい
必要条件を後から適用した集合と、v4 の早期除外・生成範囲変更後の集合を比較した。
どちらの上限でも非空集合が完全一致し、重複は0だった。

| 段階 | N<=100,000 | N<=200,000 |
|---|---:|---:|
| 凍結 v3 の厳密再構成候補 | 24,270 | 110,604 |
| 端点除外後 | 21,359 | 99,374 |
| 5進平方条件後 | 16,402 | 76,816 |
| 法125・169・121・49の射影後 | 8,711 | 41,737 |
| 臨界素数の拡張後 | **8,710** | **41,736** |
| v3 からの候補減少率 | **64.1121%** | **62.2654%** |

この表は重複を差し引くための固定した順序である。実装の実行順とは一致しない。
例えば v4 は5進条件を `permitted[u]` と `permitted[v]` に前計算し、
既存の有限体表より先に使用する。

| 生成・検査段階 | v3、100,000 | v4、100,000 | v3、200,000 | v4、200,000 |
|---|---:|---:|---:|---:|
| CRT と法19ホイール後の生成数 | 54,958,196 | 51,095,175 | 240,853,779 | 225,902,341 |
| 付値・一次元表の通過数 | 32,731,989 | 21,207,533 | 142,481,513 | 93,964,641 |
| 厳密再構成候補 | 24,270 | 8,710 | 110,604 | 41,736 |
| 原始3距離診断点 | 10 | 7 | 22 | 12 |
| 4距離解 | 0 | 0 | 0 | 0 |

3距離診断点が減るのは正しい。追加したのは4距離に必要な条件であり、
従来の3距離点をすべて保存する条件ではない。予測した診断点集合とも完全一致した。

検証結果は `extended_set_validation_100000.json` と
`extended_set_validation_200000.json`、検証コードは `verify_extended.cpp`。

## 採用した数学的除外

### 1. 生成区間の端点を除外

4距離解では `v=0` と `u=n` が不可能なので、各 CRT 等差数列を最初から

\[
\boxed{h+1\le u\le n-1}
\]

に制限する。`h>=n-1` の行は空になる。候補を生成してから捨てる処理ではなく、
最初の項と上端を変更する。元の区間に戻す検証用オプションも残した。

`v=0` は `Y=N/2` で、中線の全支持直線の不存在を使う。
`u=n` は `X=-A,Y=0` で、辺の全支持直線の不存在を使う。
全平面への適用、Fermat の下降および Barbara 2011 の一次出典は
`../research_v4_math/endpoint_exclusion.md` に記録されている。

### 2. 5進平方条件を一次元の表へ吸収

`5` が `n` を割らず、既存の法5射影を通るとき、`u≡±n (mod5)` なら

\[
W=n^2-u^2
\]

が5進平方でなければならない。`v` も同様。
`W=0` は許容し、非零なら付値が偶数で、5の冪を取り除いた単元部分が
法5で `1` または `4` になる必要がある。

この条件は再構成の判別式積

\[
(n^2-u^2)(n^2-v^2)(2n^2-(u-v)^2)
\]

と既存の法5条件から導かれる。証明と元の実装は
`../research_v4_local/lifted_projection.hpp` の `FifthPowerCondition`。
元のヘッダは変更していない。

高速化では、各単元 `n mod125` について法125で付値1または2の段階で失敗する
**44個の剰余**を先に計算する。その剰余位置だけ `permitted` を0にし、
より高い付値になり得る `u≡±n (mod125)` の **2剰余**だけ元の厳密判定を呼ぶ。
法125で未確定の枝を捨てていない。

高速表と元の定義は全 `n<=1000`、および
`n=15624,78124,999984,999996,1000000` の全 `0<=u<=n`、
合計 **3,595,233位置**で一致した。この大きい n での比較は表の単体検証であり、
探索全体を200万まで実行したという意味ではない。

また、v3 の全24,270組／110,604組について、一次元判定を使わず上の
判別式積全体を128ビット整数で計算した5進平方判定とも一致した。

### 3. 通常の素数冪射影

法 `125,169,121,49` の四距離配置を全て列挙し、署名付き半径差の射影表を使う。
対応する素数が `n` を割る場合は、その表を適用しない。
法125の射影が法25を含意するため、実探索で法25を重複検査しない。

射影表は全座標 `(x,y)` から作り、独立に全第一半径 `A` と差 `(u,v)` から
座標を再構成する方法で全表を照合している。0や非単元の半径、全符号を含む。
正方形内部という仮定は置いていない。

### 4. 臨界素数の拡張

`../research_v4_math/critical_extension.hpp` は、`17<=p<=281`, `p≡1 (mod4)`
の全26素数の基本射影を生成する。さらに41・113・137・257では、四次式の
零剰余に限って次の桁の条件も使う。`v_p(n)=2s` かつ `v_p(h)=s` の行だけに適用する。

現在の算術上限では `12|n` かつ `p^2|n` より `p<=sqrt(1000000/12)<289`。
5と13の臨界行は既存の v3 条件で除かれているため、この範囲で取り得る
残りの臨界素数は全てカバーする。

ヘッダは独立な正規化半径モデルと、全3,794個の基本剰余および
99,268個の次桁剰余で照合済み。詳細は
`../research_v4_math/critical_lift.md`、`critical_sparse.md` と検証証明書にある。

100,000と200,000の双方で、v3 候補から独立に拒否される例は次の2組だった。

| `(n,u,v)` | 条件 | 通常の素数冪射影との重複 |
|---|---|---|
| `(20172,15744,10865)` | 41の次桁 | 端点・5進条件・4射影を全て通る。独立な追加1組 |
| `(33708,31641,30740)` | 53の基本射影 | 通常の素数冪射影でも拒否される |

したがって全追加条件の最後に残る新規拒否1組は41の例である。

## 採用・不採用を分けた生成器の実験

### 採用：法19の重複検査を省略

既存の法19ホイールは、CRT 等差数列から法19の四距離条件を通る項だけを生成する。
生成後の同じ法19判定は常に真なので省略できる。`--keep-redundant19` で元に戻せる。
ホイールで生成された候補全てについて、法19を含む条件と省略した条件が
同じ結果になることも生成器検証で確認した。

### 不採用：gammaを早く判定すれば必ず速くなるわけではない

次の5方式を実装した。

| `--gamma-stage` | 内容 |
|---|---|
| `late` | 既存の有限体・原始性条件の後で gcd により判定。既定 |
| `table` | 分母ごとに全uのgammaを前計算し、一次元配列を参照 |
| `rules` | h行ごとの素数冪分類で判定 |
| `generation` | CRTと法19による生成中に素数冪分類を判定 |
| `lift` | 長い等差数列だけgammaの周期でさらにCRT持上げ |

素数冪の高い付値 `e/2<k<e` では、低い枝 `v_p(u)=e-k` に加え、
**`v_p(u)=v_p(u-h)=k` の高い枝も保持する**。両枝を残す必要がある。
例えば `n=125,h=25` の `u=30` と `u=50` は異なる2枝の回帰例。

100,000で生成側gammaは生成数を
`54,958,196 -> 54,820,847`、約0.25%しか減らさなかった。
CRT周期持上げは15,944数列を98,076枝へ展開し、初回比較では遅くなった。
コンパイル時分岐を使った3対比較でも、生成側gammaは `late` より遅かった。
有効候補を落とさない実験オプションとして残し、既定にはしていない。

100,000と200,000の最適化だけの比較、全生データ、当時のソースは
`optimization_benchmark.json`、`prototype2_source.txt`、`prototype2_record.json`。
初期の方式別集合照合は `*_parameters_100000.csv` と `prototype1_source.txt`。
これらは新しい数学的条件を追加する前の比較であり、最終v4の速度比較とは分ける。

## 再現と検証

プロジェクトのルートから：

```sh
g++ -O3 -std=c++17 all_plane_gap_v4.cpp -o all_plane_gap_v4
./all_plane_gap_v4 100000 --validate
g++ -O3 -std=c++17 research_v4/verify_extended.cpp -o research_v4/verify_extended
./research_v4/verify_extended 100000
./research_v4/verify_extended 200000
```

`--validate` は既存の独立 CRT 生成器との比較、正の3距離例の検証、法19ホイール、
gamma 素数冪分類と区間制限、素数冪射影表、5進表の一致を確認する。
v4の生成器部分だけでも33,223行・212,780個のCRT候補のgcd定義との比較を行う。

通常のオプションは `--min-denominator L`、`--audit-three CSV`、
`--audit-parameters CSV`。研究・切り分け用には次がある。

```text
--reference-v3
--no-new-filters
--keep-redundant19
--no-five-adic
--five-adic-late
--slow-five-adic-mark
--no-prime-power-projections
--no-endpoint-pruning
--no-critical-extension
--gamma-stage late|table|rules|generation|lift
```

`--no-new-filters` は新しい数学的条件と端点除外を全て止め、最適化だけを残す。
`--reference-v3` は凍結した v3 の検索関数をそのまま呼ぶ。
診断点やパラメータの参照集合を比較するときは、どの必要条件を有効にしたかを一致させる。

## 最終計測・ファイル参照

最終の交互ベンチは `final_benchmark.json`。同一バイナリの追加条件無効/有効と、
凍結した外部 v3 実行ファイルを、各上限3回ずつ交互順序で1プロセスずつ実行する。
別に5進表の高速・元実装・後判定を100,000で3回ずつ比較する。
ソースとバイナリのSHA256・生の全カウンタを同JSONに保存する。
速度の結論では最終の直接比較を使い、初期実験の速度比を掛け合わせない。
`benchmark_final.py` の再実行は履歴を保護するため `final_benchmark_rerun.json` に保存する。

| 上限 | 外部v3・中央値 | 同一v4バイナリの追加条件なし・中央値 | v4既定・中央値 | 対外部v3のペア速度比中央値 | 追加条件なしに対するペア速度比中央値 |
|---|---:|---:|---:|---:|---:|
| 100,000 | 1.62568秒 | 1.60847秒 | **1.39991秒** | **1.1161倍** | **1.1178倍** |
| 200,000 | 6.93522秒 | 6.56375秒 | **6.08097秒** | **1.1578倍** | **1.0821倍** |

「各時間の中央値の比」と「各ペアの速度比の中央値」は異なる統計量である。
ここでは生の3ペアを保存し、右2列には後者を示した。マシン負荷やコード配置に
よる変動があるため、別の環境で同じ倍率になるとは限らない。

5進判定の配置比較は100,000の3回中央値で、高速markが1.40259秒、元のmarkが
1.50811秒、後判定が1.45040秒だった。高速markを既定に採用した。

候補の約64%減が、総時間の約64%減を意味しない点にも注意が必要である。
費用の大きいCRT列挙・初期検査は大部分が残り、生成数の減少は100,000で約7%に
とどまる。gammaの前倒しが遅くなった結果も含め、生成コストを実測して採否を決めた。

最終参照集合は `final_parameters_100000.csv`、`final_three_100000.csv`、
集計は `final_100000.json`。依存・ハッシュの記録は `implementation_manifest.json`。
この集計JSONの時間にはCSV出力が含まれるため、速度の比較には上記ベンチJSONを使う。
