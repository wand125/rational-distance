# 分母 10^7 に向けた整数演算の監査と v5

2026年11月5日（日本時間）、mathematics-52。
凍結版（v2・v3・v4、`all_plane_sieved.cpp`）は変更していない。
v5 は `all_plane_gap_v5.cpp` と `wide_arith_v5.hpp` の 2 つの新しいファイルで、v4 を `#include` して再利用する。

## 1. 分母 10^7 での中間値の上界

記号は `arithmetic_bounds_v2.md` と同じ。N ≤ 10^7、0 ≤ q ≤ p ≤ N とする。
上界の証明は v2 の文書の §1 がそのまま使える（N の大きさに依らない不等式である）。
ビット数は N = 10^7 での正確な整数値から数えた（`research_v5/bounds.py` と同じ計算）。

| 量 | 上界 | ビット数 | 凍結版の型 | 10^7 で |
|---|---|---:|---|---|
| N², U, V, \|Q\| | N² | 47 | i128 | 安全 |
| T | N³ | 70 | i128 | 安全 |
| R | 2N⁴ | 95 | i128 | 安全 |
| U·V | N⁴ | 94 | i128 | 安全 |
| W = 2N² − (p−q)² | 2N² | 48 | i128 | 安全 |
| **K = U·V·W** | 2N⁶ | **141** | 符号付き i128 の積 | **あふれる** |
| **√K** | √2·N³ | **71** | u64（`isqrt` の戻り値） | **あふれる** |
| T ± √K | | 72 | i128 | 安全 |
| **A**（非負の根） | N³ | **70** | i64 へ変換（`a=i64(A)`） | **あふれる** |
| 2Ap, 2Aq | 2N⁴ | 95 | i128 | 安全 |
| **X, Y** | \|X\|,\|Y\| ≤ N³ | **70** | i64 へ変換 | **あふれる** |
| **X²+Y² など 3 つの恒等式** | 2(N³+N)² | **141** | i128 | **あふれる** |
| **第 4 距離 D² = (N−X)²+(N−Y)²** | 2(N³+N)² | **141** | i128→u128、u64 の平方根 | **あふれる** |

あふれるのは厳密再構成（`evaluate`）と、第 4 距離の判定（`accept`）だけである。

生成側は n = N/2 ≤ 5×10⁶ を u32 で扱い、次の理由で 10^7 でも安全である。

- 剰余・添字の積は u64 へ広げてから計算している（`u64(h)*idempotent`、`u64(n-u)*(n+u)` など）。u32 同士の積で n² に達するものはない。
- CRT の素因数は 7 個まで。最初の 8 素数の積 9,699,690 は 5×10⁶ を超える。128 個の剰余類の配列で足りる。
- 統計の u64 カウンタで最大の `dense_even_pairs` は 61 ビット。
- `permitted_scale` の u0²+v0²−n0² は 45 ビットで、i64 に収まる。
- 臨界素数の表（`critical_extension.hpp`）は p ≤ 281 まで。10^7 では 12p² ≤ n から p ≤ 641 までの臨界素数が現れ得る。表にない素数では追加の除外をしないだけなので、判定は誤らない。除外が少し弱まるだけである。

メモリは、`ArithmeticTables` の CRT 計画が n ≤ 5×10⁶ で 1 プロセスあたり約 440 MB になる。

## 2. v5 の直し方

上界 A ≤ N²/2 による切り捨ては使わない。これは 4 距離解だけに成り立つ上界なので、使うと 3 距離の診断点の集合が変わる。
代わりに、あふれる量を正確な整数で計算する。

- **K**：U·V（94 ビット）を u128 で作り、W（48 ビット）との積を 256 ビットの符号なし整数（4 つの 64 ビット語）で正確に作る。
- **平方判定**：まず剰余で平方でないものを除く。法は 64・63・65・11 で、平方剰余の表は全部の剰余を 2 乗して作るので正確である。残ったものは、ビットごとの復元法で整数平方根を正確に求め、r² = K を 256 ビットで確かめる。浮動小数は使わない（凍結版は浮動小数の初期値を整数で補正していた）。
- **A・X・Y**：i64 へ変換せず、i128 のまま扱う。コールバックも i128 を受け取る。
- **恒等式の検査と第 4 距離**：各平方を 256 ビットで正確に作って比べる。D² の平方判定も同じ関数で行う。
- **原始性・偶奇・mod 4・mod 3 の条件**：gcd は |X| mod N と |Y| mod N から求める。gcd(N, a) = gcd(N, a mod N) なので結果は同じ。剰余の判定は i128 の % で、i64 のときと同じ符号の規則に従う。
- 入力の上限は 10^7。範囲外の (N, p, q) が渡されたら例外で止める。√K が証明した上界を超えた場合も例外にする。

`evaluate_v5` は、凍結版の `evaluate` と同じ式・同じ根の順序・同じカウンタ・同じ条件の順序をとる。違うのは整数の幅だけである。
したがって、凍結版が正しく動く範囲（N ≤ 2^21 − 1）では、出力は数学的に同じになる。
それより上では、凍結版にはない正確さを与える。

## 3. 判定が変わらないことの確認

v5 の `--validate` は、v4 の全検証に加えて次を確かめる。

- 256 ビット演算：r < 2^127 の各ビット幅で、r²・r²−1・r²+2r の平方根と平方判定を調べる（約 72 万件）。積は 64 ビット語に分けた別の計算と照合する。
- 再構成の総当たり：N = 1..12 で、証明済みの半径の中の全整数点と完全一致する（外部の点を含む）。
- 凍結版との一致：N ≤ 400 の全 (p, q) と、N ≤ 2×10⁶ の乱択 300 万組（両方の条件モード）で、点の列とカウンタが凍結版の `evaluate` と完全一致する。計 1,382 万組。
- 大きな N：N ≤ 12 の 3 距離点を k 倍して N を 10^7 近くまで拡大し、拡大した点がすべて再現されることを調べる（116 系列）。ここでは K・√K・A・平方和が 64・128 ビットを超える。
- Python の多倍長整数による独立の照合：`--wide-selftest` が書く 2 万件の積と整数平方根を、`research_v5/check_wide_selftest.py` で照合する。

探索全体の照合は `research_v5/compare_v4_v5.py` で行う。凍結 v4 と v5 を同じ分母区間で走らせ、次の 3 つの一致を求める。

- 非空のパラメータ集合（`--audit-parameters` の全行）
- 診断用の 3 距離点（`--audit-three` の全行）
- 全カウンタ（時間を除く）

結果は `progress_v5_2026-11-05.md` に記録する。

## 4. 分割実行

`run_sharded_v5.py` は分母 1〜B を、仕事がほぼ等しい多数の区間に分ける。区切りは 24 の倍数で、平方根に沿って置く。

- 区間ごとに出力を確かめてから `.done.json` を書く。再起動すると済んだ区間は飛ばすので、回収で失うのは走っていた区間だけである。
- 複数の台で別々の区間を受け持ち、最後に `merge` でまとめる。まとめでは次を確かめる。
  - 全区間がちょうど 1 回ずつあること
  - 設定とソースのハッシュが同じであること
  - 分母の被覆が理論上の組数と一致すること
  - 3 距離点と 4 距離点のすべての等式を Python の整数で検査すること
