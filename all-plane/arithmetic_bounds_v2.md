# 全平面探索の整数演算上限の監査

このノートは、新しい探索版の上限を検討するための数学的・実装上の監査です。
既存の `all_plane.cpp`、`all_plane_sieved.cpp`、`all_plane_gap.cpp` は変更していません。

## 1. 既存の再構成式を変更せずに安全に扱える範囲

既存の評価関数について、

```
1 <= N <= 2,097,151 = 2^21 - 1
0 <= q <= p <= N
```

なら、現在の符号付き128ビット整数・64ビット平方根・64ビット座標の演算範囲が安全です。
実用上の丸い入力上限としては2,000,000を採用できます。
2,097,151以下で最大の24の倍数は2,097,144です。

### 正の根に対する、以前より強い一般上界

```
Q=p²+q²-N²
T=p(N²-p²)+q(N²-q²)
R=(N²-p²)²+(N²-q²)²
K=(N²-p²)(N²-q²)(2N²-(p-q)²)
```

とすると、距離Aは4QA²-4TA+R=0を満たします。
この方程式の非負の根について、偶奇を仮定せずに

**A <= N³**

が成り立ちます。

まず0<=t<=Nなら

```
t(N²-t²)=t(N-t)(N+t) <= (N²/4)*2N=N³/2
```

なのでT<=N³です。またK<=2N⁶です。

- Q>0なら、実根は非負で、その和はT/Q。従って各根A<=T/Q<=N³。
- Q<0なら、正の根は(√K-T)/(2|Q|)<=N³/√2<N³。
- Q=0,T>0ならp,qは正整数でp²+q²=N²。T=pq(p+q)>=N²、R=p⁴+q⁴<=N⁴より、A=R/(4T)<=N²/4。
- Q=T=0ならR>0で、根はありません。

この上界は3距離を再構成する全ての根に適用できるため、診断用の3距離候補を減らしません。

### 各中間値

座標式から-A<=X,Y<=N/2です。従って|X|,|Y|<=N³であり、
N-X,N-Y<=N³+Nです。既存コードの全ての平方和は、保守的に2(N³+N)²以下に収まります。

M=2²¹-1で次の整数不等式を直接確認できます。

```
M³+M <= 2^63-1
2M⁶ <= 2^127-1
2(M³+M)² <= 2^127-1
```

左辺はNについて単調なので、これで全範囲の64ビット座標と128ビット積を覆います。
T±√Kなどの一時的な分子は128ビットで保持されるため、64ビットを超えても問題ありません。
√Kおよび平方和の平方根は2^64未満です。

### 支配的な制限

コードのKは次の形で計算されます。

```cpp
const u128 K = u128(U*V*(2*nn-delta*delta));
```

積を計算する時点では符号付き128ビットです。
最後にu128へ変換しても、それより前の符号付きオーバーフローは防げません。
N=2²¹、p=q=0ではK=2¹²⁷となり、符号付き128ビットの最大値を超えます。
したがって上限を増やすときは、型変換位置を含めた監査が必要です。

CRT関連の容量も上の上限では足ります。
n<=1,048,575で異なる素因数は最大7個です（最初の8素数の積9,699,690より小さい）。
7個の素数冪を保持する表と、128個のCRT剰余類を保持する配列はこの範囲を覆います。
32ビットの添字や剰余類の加算、64ビットの候補数カウンタにも余裕があります。

## 2. 実際の4距離解にはA<=N²/2という上界もある

これは中線上の不存在定理を使わずに示せます。
4距離をA,B,C,Dとし、

```
u=A-B, v=A-C, w=A-D, t=u+v-w
```

と置きます。British flag恒等式から

```
2At=u²+v²-w²
```

です。三角不等式より|u|,|v|<=N、|w|<=√2Nなので、右辺の絶対値は2N²以下です。
原始4距離解では全距離が奇数なので、tが非零なら|t|>=2。
従ってA<=N²/2です。

t=0の場合はw=u+vなのでuv=0となり、点は中線X=N/2またはY=N/2にあります。
n=N/2、残りの整数座標をZとすれば

```
(A-Z)(A+Z)=n²
```

です。二つの因子は正整数なのでA<=(n²+1)/2<=N²/2（N>=2）。
従ってこの例外でも同じ上界が成立します。

各頂点を出発点に同じ議論ができるので、4距離すべてがN²/2以下です。

この上界は「4距離解である」という仮定を使います。
3距離点の診断集合をそのまま保存したい実行では適用してはいけません。
探索をさらに拡張する場合、4距離探索に限り、座標の64ビット変換や平方和の計算より前に
A>N²/2を除外する使い方ができます。

## 3. さらに大きなNで必要な変更

例えばN=10,000,000ではK<=2N⁶は141ビット必要です。
その平方根も71ビット必要なので、現在のu64を返す整数平方根関数は使えません。

軽い候補生成・合同式検査はそのまま使い、まれに残る候補の再構成だけで
固定256ビット整数または任意精度整数を使う方法が考えられます。
N=10^7ではT,Q,R自体は128ビットに収まりますが、Kの積と平方判定は拡張が必要です。
平方根は128ビットで受け取ります。

4距離探索なら、得られたAに先にA<=N²/2を要求することで、後段の座標と平方和を
再び64/128ビットで安全に扱えます。ただし3距離の診断点数は変わり得ます。

Nを32ビット全域まで考える場合はKだけでなくRにも256ビットが必要です。
それ以前にCRT素因数配列・剰余類配列・候補数カウンタ・前計算メモリにも別の上限があります。
Kの型だけを広げて入力上限を上げることはできません。

## 4. 強化した差hの素数指数条件の確認

l^e||n、l==3 mod8とします。
既存の原始性条件からu,vのl進指数は0またはe以上です。
またGOODの差条件からval_l(h)<=e、h=u-vです。

- u,vの一方だけがlの倍数ならhは単元。
- 両方がl^eの倍数ならhもl^eの倍数。
- 両方が単元なら、座標の整数条件A==-u==-v mod l^eからhもl^eの倍数。

したがって

```
val_l(h) is either 0 or e
```

が必要です。これは指数1..e-1の差の族をまとめて除外できます。
l==7 mod8なら同じ議論で0またはe以上ですが、GOODによる上側の制限がないので、
e+1以上を除外してはいけません。l==5 mod8ではAがl進単元とは限らず、この強化を
そのまま適用してはいけません。

## 検証ファイル

- `arithmetic_bounds_v2_checks.json`：最大値に対する正確な整数不等式。
- `arithmetic_bounds_v2.cpp`：境界近くのK、整数平方根、外部の3距離点、最大7素因数のCRTを調べる追加検証。
- `arithmetic_bounds_v2_sanitizer.txt`：未定義動作検出付きの実行結果。

これらは安全な上限の証明を補助する検査であり、代表例だけから全範囲の安全性を推測するものではありません。
